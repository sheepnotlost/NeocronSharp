# Automatic detection update

The default app no longer asks for coordinate or empty-slot calibration. Previous saved points and reference samples are ignored by the desktop app.

Before every cycle:

1. Capture a fresh image of the bound foreground game client.
2. Find the Processor title and independently verify Start; reject hidden, clipped, or ambiguous matches.
3. Check that the research tool is present and all other Processor input slots are empty.
4. Find Inventory using opaque caption text and verify Max Load and Free Load at the corresponding offsets. Reject the navigation bar's Inventory label when the load headers are absent. Then find the requested T/E/A/L stack by its visible label and part icon.
5. Transfer one part to the second input slot.
6. Locate the quantity dialog using its opaque title text and Half control. Verify that its numeric field is exactly 1. If necessary, enter 1 and verify it before confirming. A correct default 1 is not retyped.
7. Find the Processor again before pressing its current Start button.
8. Track the Processor while waiting for its input to clear. A missing window never counts as an empty slot.

The Processor may move between runs, and the quantity dialog can move independently. A failed search never returns an old position as a fallback. A short bounded search tolerates brief transitions; persistent absence or ambiguity stops without retrying the part.

The final result stays in the Processor. Each subsequent research start returns the previous result automatically.

Research is monitor-only, without per-part durations, fixed research waits, minimum processing times, or research time limits. An occupied input keeps monitoring until completion, focus loss, or app closure. Existing research timing settings are removed when profiles load/save.
